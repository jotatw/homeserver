# HomeServer — Roadmap v1.0

> Roadmap de evolução a partir do Baseline v0.1.0.

Este roadmap descreve **fases de implementação**, não substitui a visão de longo prazo em `planning/vision.md`.

A regra deste roadmap é incremental: cada fase deve produzir uma base utilizável antes que a próxima seja iniciada.

---

## FASE 0 — Baseline

**Pergunta:** qual é exatamente o estado do projeto?

Objetivo:

- registrar o estado atual;
- executar o Quality Gate;
- documentar arquitetura, serviços, scripts e testes;
- registrar problemas e limitações;
- estabelecer o Baseline v0.1.0.

**Estado:** 🟡 Em andamento

Documento de referência:

- `planning/release/baseline-v0.1.0.md`

---

## FASE 1 — Organização e padronização

**Pergunta:** a base é consistente o suficiente para evoluir?

Escopo:

- padronização de `scripts/`;
- revisão de nomenclatura;
- responsabilidades claras por camada;
- remoção de duplicações;
- revisão de configurações;
- consolidação de documentação técnica;
- atualização das convenções de contribuição.

**Fora do escopo da FASE 0:** qualquer refactor antecipado.

**Estado:** ⚪ Planejada

## FASE 4 — Serviços

**Pergunta:** os serviços externos estão integrados de maneira previsível?

---

## FASE 7 — Segurança

**Pergunta:** o sistema possui uma base segura por padrão?

Escopo:

- autenticação;
- autorização;
- permissões;
- secrets;
- Docker;
- API;
- firewall;
- exposição de serviços;
- logs;
- hardening;
- testes de segurança.

---

## FASE 8 — Automação

**Pergunta:** tarefas repetitivas podem ser executadas pelo próprio sistema?

Escopo:

- hooks;
- automações de dispositivos;
- backup automático;
- startup/shutdown;
- scheduler;
- tarefas recorrentes;
- recuperação automática quando apropriado.

Automações devem ser opcionais quando dependerem de serviços externos.

**Estado:** ⚪ Planejada

---

## FASE 9 — UX / facilidade de uso

**Pergunta:** uma pessoa nova consegue utilizar o servidor sem conhecer sua implementação?

Escopo:

- Quick Start;
- primeiro acesso;
- onboarding;
- mensagens de erro;
- estados vazios;
- acessibilidade;
- experiência mobile;
- consistência entre Homepage e App;
- testes com usuário novo.

O objetivo não é esconder a complexidade técnica da administração, mas impedir que ela seja necessária para o uso cotidiano.

**Estado:** ⚪ Planejada

---

## FASE 10 — v1.0

**Pergunta:** a base está pronta para ser tratada como uma primeira versão estável?

Critérios:

- instalação limpa validada;
- upgrade validado;
- reboot validado;
- serviços essenciais estáveis;
- backup e restauração validados;
- segurança revisada;
- Quality Gate verde;
- documentação completa;
- usuário novo consegue instalar e utilizar;
- problemas críticos inexistentes;
- limitações conhecidas documentadas.

**Estado:** ⚪ Objetivo

---

## Relação com a visão do projeto

Este roadmap operacionaliza a evolução do repositório sem substituir as fases de valor definidas em `planning/vision.md`.

A visão continua respondendo às perguntas de produto e plataforma; este documento organiza o trabalho técnico necessário para chegar a uma versão v1.0 coerente.

---

## Regra de evolução

Nenhuma fase deve ser considerada concluída somente porque o código existe.

A conclusão exige:

1. implementação quando aplicável;
2. testes;
3. documentação;
4. evidência;
5. validação de uso;
6. registro das limitações restantes.

Uma fase posterior não deve mascarar uma pendência crítica de uma fase anterior.
