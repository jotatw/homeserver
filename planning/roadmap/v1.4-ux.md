# HomeServer v1.4 — Roadmap de UX (documento oficial)

> **A Homepage deve evoluir para ser a porta de entrada do HomeServer, enquanto o HomeServer App evolui para ser a interface principal da plataforma.**

## Objetivo

A Homepage é a porta de entrada do HomeServer.

Ela apresenta o sistema de forma simples, orientada às tarefas do usuário e preparada para integrar o HomeServer App.

- Não é um painel de monitoramento.
- Não substitui o App.
- Não expõe a infraestrutura.

**Meta mensurável**: em menos de 10 segundos, um usuário que nunca viu o HomeServer deve entender onde estão seus arquivos, o que pode fazer e se o servidor está funcionando — sem interpretar métricas técnicas.

## Evolução de papel

```
Hoje        → Homepage como dashboard
v1.4        → Homepage como portal
v2.0        → Homepage como landing page (Entrar no HomeServer)
```

- A Homepage **acolhe, orienta e direciona**.
- O App **administra e concentra a experiência diária**.

## Critérios para novos componentes

Um novo card só pode entrar na Homepage se responder pelo menos um destes objetivos:

- ajudar o usuário a executar uma ação;
- informar um estado importante;
- facilitar o acesso a uma funcionalidade frequente.

Caso contrário, pertence ao HomeServer App.

## Design Principles (bússola visual)

O HomeServer utiliza um design funcional. Cada elemento deve ter uma finalidade clara.

A interface privilegia:

- simplicidade;
- legibilidade;
- consistência;
- baixo ruído visual;
- navegação previsível.

O usuário deve reconhecer rapidamente onde está e o que pode fazer.

## Fase A — Arquitetura visual

### v1.4.0 — Organização
- **4 grupos**: Meu espaço · Aplicações (renomeado de "Serviços") · Administração · Sistema
- Modos: Usuário (Meu espaço + Aplicações) · Admin (+ Administração) · Sistema (+ Sistema)
- Remover "Favoritos" e "Links" (quebrado → esconder)
- **Mover** widgets técnicos (storage/events/status/devices/hardware/power) para o grupo Sistema — elimina redundância

### v1.4.1 — Layout
- Header compacto e útil: `HomeServer | data | Tudo funcionando | métricas discretas`
- Menos altura de card, mais espaço **entre** grupos
- Rodapé discreto: `HomeServer v1.4.x · Última atualização · Sistema saudável`

### v1.4.2 — Hierarquia
- Cards como ações: título = ação ("Arquivos / Gerenciar arquivos", "Projetos / Abrir Gitea"); software vira detalhe
- Meu espaço maior/destacado · Sistema menor
- Estados: 🟢 Online · 🟡 Atenção · 🔴 Indisponível (cor + indicador)
- Ícones só nas categorias; tipografia com pesos

## Fase B — Experiência

### v1.4.3 — Fluxo
- Revisar nomes/navegação; reduzir cliques
- Preparar App como destaque ("Administração → HomeServer App")

### v1.4.4 — Polimento
- Loaders, estados vazios, erros amigáveis, animações discretas, revisão geral

### v1.4.5 — Design System
- `docs/design/`: `principles.md`, `colors.md`, `typography.md`, `spacing.md`, `icons.md`, `components.md`
- Padroniza altura dos cards, espaçamentos, fontes, paleta, ícones, estados
- Base compartilhada Homepage + App (consistência no ecossistema)

## Execução (mecânica)

Cada release:
1. Editar `modules/homepage/config/` (repo) → copiar para `/srv/docker/compose/homepage/config/` (runtime, preservando service token)
2. CHANGELOG + tag `v1.4.x`
3. Push `github` + `origin` (gitea)
4. `hs update check` → `update:true` antes, `false` depois; validar visual em 3 modos

## Riscos conhecidos
- Nomes de grupos devem bater exatamente com o filtro do `custom.js`
- Nunca sobrescrever o runtime inteiro (perderia o service token)
- Widgets **movidos**, não duplicados
