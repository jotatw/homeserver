# Optional and Specialized

## Objetivo

Reserva uma fronteira de planejamento para funcionalidades que não pertencem à base mínima da plataforma e podem ser instaladas conforme necessidade.

## Escopo previsto

- módulos experimentais;
- serviços especializados;
- integrações específicas de um ambiente doméstico;
- funcionalidades futuras que ainda não justificam um grupo próprio.

## Regra de entrada

Ser opcional não significa escapar da arquitetura modular. Um módulo deste grupo deve obedecer aos mesmos contratos de Definition, Instance, recursos, ownership, integrações, operações, compatibilidade e validação.

## Evolução

Quando uma categoria amadurecer e possuir identidade própria, poderá ser promovida para um grupo dedicado sem alterar o contrato arquitetural dos módulos.

## Estado

Grupo planejado e aberto à expansão. Nenhuma implementação é exigida para fechar esta etapa de planejamento.
