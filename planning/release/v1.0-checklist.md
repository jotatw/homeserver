# v1.0 — Release Checklist

> Matriz de prontidão do **v1.0.0** (primeira release estável da linha atual).
> Critérios: [`definition-of-ready-for-release.md`](definition-of-ready-for-release.md)
> · Processo: [`release-process.md`](release-process.md) · Endurecimento: [`hardening.md`](hardening.md)

| Área | Estado | Observação |
|---|---|---|
| Instalação | 🟡 | `install.sh` validado (DinD módulos 4/4 + produção); **Zero Knowledge Test** pendente |
| Upgrade (hs update, linha v1) | 🟡 | fluxo corrigido (linha v1) e testado; upgrade real v. anterior → v1.0.0 pendente |
| Reboot | 🟡 | timers/containers `unless-stopped`; reboot real a validar |
| TLS / HTTPS local | ✅ | CA interna + certificados validados (`hs tls`) |
| Atualização de pacotes | ✅ | `hs update os` validado; upgrade real aplicado (apt) |
| Backup / Recovery | 🟡 | backup diário ativo; restauração a validar em teste |
| Segurança / hardening | 🟢 | authz (403), secrets fora do repo, dry-run real, containers sem privileged |
| Documentação | 🟢 | `docs/` reorganizada por objetivo; links verificados; `planning/` indexado |
| Arquitetura modular (M1) | ✅ | referência conceitual consolidada (`planning/architecture/`) |
| Quality Gate | 🟢 | CI verde (unit/API/session/smoke); `hs version` requer a tag v1.0.0 |
| Publish | ⬜ | `publish.yml` validado na RC; a executar na v1.0.0 |
| Zero Knowledge Test | ⬜ | máquina limpa + somente documentação |

## Bloqueios para a tag (obrigatórios)

- [x] Quality Gate sem falha (unit/API/session/smoke + `hs version` após a tag).
- [x] Documentação atualizada e consistente.
- [x] Dependências auditadas (`npm audit` 0; imagens pinadas).
- [ ] ZKT (pode ser executado após a release, como critério de acompanhamento).
- [ ] Decisão explícita do mantenedor de publicar o v1.0.0.

> A v1.0.0 não depende da implementação modular (M1): a M1 é referência
> conceitual; sua implementação segue nas fases pós-v1.
