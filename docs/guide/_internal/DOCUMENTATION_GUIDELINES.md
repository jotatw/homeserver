# Guia de Escrita

## Objetivo

Este documento define os princípios editoriais utilizados durante a escrita do HomeServer Guide.

Seu objetivo é manter consistência entre todos os capítulos, garantindo que o guia preserve a mesma identidade, linguagem e filosofia durante toda a sua evolução.

Este documento é destinado aos autores da documentação e não faz parte do conteúdo apresentado ao leitor.

---

# Sobre o Guia

O HomeServer Guide é uma documentação complementar baseada no desenvolvimento de um HomeServer real.

Seu propósito não é ensinar uma única forma de construir um servidor doméstico, mas compartilhar experiências, decisões de arquitetura e aprendizados obtidos ao longo do projeto.

O HomeServer é utilizado como um estudo de caso.

As soluções apresentadas representam escolhas feitas durante o desenvolvimento da plataforma e devem servir como referência, não como regras.

---

# Filosofia

Tecnologias mudam.

Boas decisões costumam permanecer.

Por esse motivo, cada capítulo deve explicar primeiro o motivo das escolhas realizadas e somente depois apresentar como elas foram aplicadas.

O objetivo é incentivar o leitor a compreender os conceitos para que possa adaptá-los à sua própria realidade.

---

# Objetivos

Cada capítulo deve contribuir para pelo menos um dos seguintes objetivos.

- Apresentar um conceito.
- Compartilhar uma experiência real.
- Explicar uma decisão de arquitetura.
- Incentivar o planejamento.
- Demonstrar a evolução do projeto.
- Inspirar novas possibilidades.

---

# O que este guia é

O HomeServer Guide é:

- um guia complementar;
- um estudo de caso;
- um conjunto de experiências práticas;
- uma referência para planejamento;
- um registro da evolução do projeto.

---

# O que este guia não é

O HomeServer Guide não é:

- um curso de Linux;
- um manual de Docker;
- uma documentação oficial;
- um tutorial passo a passo;
- uma coleção de comandos;
- a única forma correta de construir um HomeServer.

Sempre que necessário, a documentação oficial das tecnologias utilizadas deve ser utilizada como complemento.

---

# Princípios da Escrita

A escrita deve ser:

- clara;
- objetiva;
- acessível;
- baseada em experiências reais;
- independente de tecnologias específicas sempre que possível.

Priorizar conceitos antes de implementações.

Explicar decisões antes de apresentar soluções.

---

# Estrutura dos Capítulos

Sempre que possível, os capítulos devem seguir uma estrutura semelhante.

## Contexto

Apresenta a necessidade ou o problema.

## A ideia

Explica o conceito de forma simples.

## A experiência deste projeto

Mostra como aquele conceito foi aplicado durante o desenvolvimento do HomeServer.

O projeto deve ser tratado como exemplo e não como regra.

## Outras possibilidades

Apresenta alternativas sempre que fizer sentido.

## O que aprendemos

Resume os principais aprendizados obtidos durante aquela etapa.

---

# Inteligência Artificial

A Inteligência Artificial é tratada como uma ferramenta de apoio.

Ela não faz parte da infraestrutura do HomeServer.

Seu objetivo é auxiliar o administrador durante atividades como:

- pesquisa;
- planejamento;
- documentação;
- desenvolvimento;
- manutenção;
- automação.

O HomeServer deve permanecer totalmente funcional mesmo sem qualquer integração com IA.

---

# Princípios do Projeto

Todo capítulo deve reforçar os pilares do projeto.

- Simplicidade.
- Modularidade.
- Organização.
- Aprendizado contínuo.
- Evolução incremental.
- Separação entre serviços e dados.
- IA como recurso complementar.

---

# Critérios de Qualidade

Antes de considerar um capítulo concluído, verificar:

- O capítulo explica um conceito?
- A decisão de arquitetura foi apresentada de forma clara?
- O HomeServer foi utilizado como exemplo e não como regra?
- O texto continuará útil mesmo que alguma tecnologia seja substituída?
- A linguagem é acessível?
- O leitor foi incentivado a compreender o conceito e não apenas reproduzir uma solução?

---

# Considerações Finais

O HomeServer Guide documenta uma experiência real.

Seu maior objetivo não é apresentar uma infraestrutura perfeita, mas registrar decisões, limitações, aprendizados e evoluções obtidas durante o desenvolvimento do projeto.

Mais importante do que reproduzir esta plataforma é compreender o processo utilizado para construí-la.

---

# O HomeServer como estudo de caso

O HomeServer utilizado neste guia representa uma implementação real desenvolvida ao longo do projeto.

Ele é utilizado para ilustrar conceitos, decisões de arquitetura e experiências práticas.

Seu objetivo não é servir como modelo definitivo, mas como um estudo de caso que acompanha toda a narrativa.

Cada decisão apresentada deve incentivar o leitor a compreender o problema antes de escolher uma solução, adaptando as ideias à realidade do seu próprio ambiente.
